# 単話添削(初見の読者に意味が通るまで書き直す)

## この工程が作り直された理由(必ず読む)

**第14話の添削を三度やり直しても、ユーザーから「添削されたとは思えない酷い内容」と言われた。** 指摘は18件あり、その大半が**「意味不明」**だった。規約違反ではなく、**読んで意味が取れない**という指摘である。

原因ははっきりしている。**添削する側が、本文を書いた側と同じ文脈を持っていたから。** 設定資料もプロットも前後の話も頭に入った状態で読むと、書かれていない情報を勝手に補って読んでしまう。「まるで見せるためのように」「明滅が駆け足になっている」「言うつもりのなかった言葉が勝手に出てきた」——**書き手には意味が通っていて、初見の読者には一文字も渡っていない**文が、三度の添削を素通りした。

だから工程の中心を入れ替えた。**添削の出発点は、規約のチェックリストではない。本文しか知らない別人格が読んで、どこで詰まったかである。**

## 手順

### 1.【必須・最初にやる】初見読者エージェントに読ませる

**Agentツールで、本文だけを渡した別エージェントを立てる。** メタコメント・`bible/`・`plot/`・前後の話は**渡さない**。渡した時点でこの工程は無意味になる。

- 使うエージェント: `general-purpose`(素の読者として読ませる。`continuity-editor`は設定を読みに行くので**ここでは使わない**)
- 渡すもの: **対象話の本文だけ**(メタコメントを外したもの。scratchpadに書き出して渡す)
- 指示すること:
  - あなたはこの作品を今日初めて読む。前の話も設定資料も読んでいない
  - **意味が取れなかった箇所を、行を引用して全部挙げる。**「たぶんこういう意味だろう」と補完しない。**補完しないと読めない文は、それ自体が欠陥**
  - **人物の行動で「なぜ今それをするのか」が分からなかった箇所を挙げる**
  - **会話で、その返しが返ってくる理由が分からなかった箇所を挙げる**
  - **結論に向かって話が急に進んだと感じた箇所を挙げる**
  - **恥ずかしい/寒い/作り物めいていると感じた箇所を挙げる**
  - 件数は絞らない。迷ったら挙げる
- **戻ってきた指摘は、原則すべて欠陥として扱う。** 「設定を知っていれば分かる」は反論にならない——読者は設定を知らない

### 2. 指摘を、直す単位ごとに束ねる

**一行パッチで潰さない。** 「意味不明」と言われた一行は、**その場面の設計が間違っている合図**である。

- **その一行だけを言い換えて済ませてはいけない。** 場面の目的(何を読者に渡す場面か)だけ残して、**段落ごと・会話ごと書き直す**
- **判定**: 直したあと、その一行の前後を初見で読んで、**書かれている事実だけで意味が通るか**。通らないなら、足りないのは言い回しではなく**出来事**
- 感情・関係・危機感は、**地の文の要約ではなく出来事で渡す**(「危ない」と書くのではなく、爪痕・霜・鎖の太さを出す)

### 3. 書き直す

`CLAUDE.md`の全規約を守るのは前提。そのうえで、**今回の指摘から立った禁止**を必ず通す。

- **【最上位】読者が補完しないと読めない文を書かない。** 比喩・体感・抽象名詞に逃げた瞬間に事故る。「駆け足の明滅」「見せるための道筋」は**何も描写していない**
- **人物に、知り得ないことを言わせない・地の文で説明させない。** ステータスの伸び方の仕組み、まだ調べていないことの断定
- **強く見せたいものは、大きさ・音・温度・傷跡で見せる。** 「格が違う」と書いても格は伝わらない。**怯えを書く前に、怯える材料を先に置く**
- **会話を結論へ運ばない。** 書き手が決めた着地(方針・取り決め・秘密の共有)へ、人物に最短距離を歩かせない。**人物の側の理由**(この子を獲られたくない、など)から言わせる。**railroadした会話は、読者に「作者の都合」として読まれる**
- **人物の性格に反する発言をさせない。** 引っ込み思案の主人公から誘わせない、勧誘させない。**その台詞を言うべき人物は誰かを、毎回問い直す**
- **不思議な現象は、必ず出所を作る。** 「誰に教わったわけでもないのに分かる」を繰り返さない。**画面表示・本人の口・相手の反応**のどれかを通す
- **独り言・引きの場面は短く。** 一人で喋らせるほど安っぽくなる。**三言まで**

### 4. 機械チェック

```bash
python3 .claude/skills/tensaku/scripts/lint.py manuscript/partNN/epNNN.md
```

文字数 / た。段落4連続 / 4文段落 / 数字混入 / 反復語 / 空行・◇書式。**これは最後の掃除であって、添削の本体ではない。**

### 5. 前提との突き合わせ(ここで初めて設定を見る)

書き直したものを、`bible/`・`plot/arcs/`・`plot/foreshadowing.md`・直前2話・後続話の鎖と照合する。**順番が逆になっていることに注意**——先に設定を読むと、初見の目が死ぬ。

- 呼称の境界(ウィン/冬夜)、仕様(表示は本人にしか見えない等)、話数レンジ制約、伏線の仕込み・回収
- 締めの型・場面構成・情報の渡され方が直前2話と3連続していないか

### 6.【必須】初見読者エージェントにもう一度読ませる

**手順1と同じ条件で、書き直した本文をもう一度読ませる。** 別エージェントを新規に立てる(前の会話を引き継がせない)。

- **1回目の指摘が消えているか**ではなく、**新しく出た指摘がゼロか**で判定する
- 指摘が残っている限り、手順2へ戻る。**「たぶん伝わるはず」で切り上げない**

### 7. 記録して、測って、出す

- 直した内容と理由を**対象話のメタコメント**に追記(「何を・なぜ」)
- 一般化できる欠陥は`CLAUDE.md`へ規則として追加(実例と直し方をセット)
- `HANDOFF.md`を更新
- **lintを実行してから**文字数を書く(実行とコミットは別のツール呼び出しに分ける)
- コミットして`claude/…`ブランチと`main`の両方へプッシュ
- 報告は日本語で、**指摘ごとに「何が問題だったか→どう直したか」**の形で並べる

## してはいけないこと

- **自分一人で読み返して「四視点で読んだ」ことにする。** 同じ人格が視点の名前を変えても、補完の癖は消えない。**外部エージェントを立てないなら、この工程をやったとは言わない**
- 設定資料を先に読んでから本文を読む(初見の目が死ぬ)
- 「意味不明」と言われた一行だけを言い換える(場面ごと直す)
- lintが通ったことを添削の成果として報告する
