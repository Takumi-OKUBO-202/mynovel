# 単話添削(厳しい読者目線での改稿)

第8〜11話のフィードバック改稿で確立した工程。**1話を、初見の読者の目で一文ずつ読み直し、`CLAUDE.md`の規約に照らして直しきる。** エージェントは使わず、本人(このセッションのClaude)が直接編集する。

**規約の本体は`CLAUDE.md`「文体規約」以下の全節。** このスキルは手順と道具だけを持つ。規約をここに複製しない(二重管理になる)。

## 手順

### 1. 前提を読み込む(本文を直し始める前に必ず)

- 対象話の本文と**冒頭メタコメント**(過去の改稿理由。同じ轍を踏まないため)
- **直前2話**——締めの型・場面構成・情報の渡され方が3話連続していないかは、並べないと判定できない
- **後続話への鎖**——対象話が触れる持ち物・状態・開示順が後の話の前提になっていないか。`bible/characters/*.md`の登場記録と`bible/timeline.md`で当たりをつけ、疑わしい話は本文を開く(例: 傷薬の本数は第11〜19話で鎖になっている。回復の開示は第12話の口頭→第13話の実演の順)
- `plot/arcs/`の該当行(その回の狙い。**冒頭の動機と山場が一致しているか**の照合元)
- `plot/foreshadowing.md`(仕込み・回収の予定に触れる編集をしていないか)
- 本文が触れるシステム・地理・人物の`bible/`該当箇所(スキル名表記・習性・方角)

### 2. 機械チェックを流す

```bash
python3 .claude/skills/tensaku/scripts/lint.py manuscript/partNN/epNNN.md
```

文字数 / た。段落4連続 / 4文段落 / 数字混入 / 反復語 / 空行・◇書式 が出る。**結果は材料であって結論ではない。** ヒットは本文を開いて文脈で判断する。

### 3. 規約に沿って通し読みする

`CLAUDE.md`の節を**チェックリストとして上から順に当てる**。とくに再発が多いのは——

- **読者の手を止めない**(三つの問い。迷ったら消す)
- **読者に伝わるか**: 指示語の指す先(直前1〜2文まで)/主人公が知り得ないこと/現在地の採点/「Aした。今日はAしなかった」対句/仕様前提の否定形/数の明示
- **話を飛ばさない**: 遭遇→戦闘の段差/場所移動の位置関係/判断の見立て/接続語の受け先/消耗の過程
- **戦闘の段取り**(戦闘がある回): 臨戦の描写→必ず一度失敗→失敗から見つけて次で使う→クレストを使う。NPCに解法を言わせない(事実と習性まで)。通知は戦闘後・効果一行付き
- **語尾・締め・型**: 締めの型が直前2話と被っていないか/ぼかした締め/意味ありげで情報のない締め/極端な短文
- **キザにしない**: 決めポーズ/脇役の過大な反応/声に出して恥ずかしいか
- **会話**: 単語だけの受けが3つ以上続かないか/その会話でしか出せない情報・感情があるか
- **呼称と境界**: ゲーム内=ウィン/現実=冬夜。ログイン・ログアウトの境界描写
- **数値・金額ゼロ**(擬音・Lv表記・段階は可)

一文ごとに「**この一文で読者に何が渡るか**」を問い、渡らない文は消す。**削って通じるなら要らなかった文。** 足すのではなく置き換える(4,000字目安を動かさない)。

### 4. 直す・記録する

- 本文を直接編集する。**会話の生きた台詞はできるだけ温存**し、直すのは地の文の癖から
- 直した内容と理由を**対象話のメタコメントに追記**する(「何を・なぜ」を1行ずつ。次の改稿者=未来の自分への引き継ぎ)
- 添削中に**一般化できる欠陥**を見つけたら、`CLAUDE.md`の該当節に規則として追加する(実例と直し方をセットで)。ユーザー指摘から直した項目は必ず一般化する

### 5. 波及を確認する

- 変更した固有名詞・持ち物・状態・開示順で**リポジトリ全体をgrep**し、他話・`bible/`・`plot/`との矛盾を潰す
- 話数レンジ制約(本数の鎖・不在期間・秘密の保持)は、**レンジ内の話を時系列に並べて機械的に照合**する

### 6. 測ってから報告する

- lintを再実行し、**文字数は必ず実測してから**報告・コミットメッセージに書く(過去に3回、実測せず書いて修正になった。**測る前に数字を書かない**)
- コミットして`claude/…`ブランチと`main`の**両方に**プッシュする
- ユーザーへの報告は日本語で、**直した箇所を「元の文→直した文/理由」の形で列挙**する。分類(蛇足・指示語・段取り…)でまとめると読みやすい

## してはいけないこと

- lintだけ流して「問題なし」と報告する(機械チェックは規約の1割しか見ていない)
- 規約に挙がった型の**新種**を見逃す——規約は実例集であって網羅ではない。判定基準は常に上位ルール「読者の手を止めない」に戻る
- 直した結果の文字数・型が直前2話と揃ってしまう(締めの型・場面構成は3話連続で同型にしない)
- メタコメント・`HANDOFF.md`への記録を省く
