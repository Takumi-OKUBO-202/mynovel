# 読者視点レビュー

書き上げた話を**まとめて読者の目で読み直し、離脱しそうな箇所を潰す**工程。`new-episode`スキルの必須工程でもある。

`continuity-editor`が見るのは設定との整合と文章の粗であり、**この工程が見るのは「読み物として成立しているか」**。役割が違うので、どちらかで代替しない。

## 手順

1. **対象を決める**
   - 原則、**直近の連続3話**。1話だけのレビューは行わない(単調さは複数話を横に並べないと判定できないため)
   - あわせて**直前2〜3話**を比較対象として特定する(こちらはレビューしない)

2. **機械チェックを先に流す**
   - 下記スクリプトで、文字数 / 4文以上の段落 / 「〜した。」の連続 / 数値・金額の混入を出す
   - **結果はエージェントに渡す材料であって、結論ではない**

3. **`reader-reviewer` エージェントを呼ぶ**
   - 対象話のパスと、比較対象の直前話のパスを明示して渡す
   - 機械チェックの結果も一緒に渡す
   - **下記「コピー改稿から抽象化したレビュー観点」も必ずプロンプトに含める**

4. **指摘をユーザーに要約報告する**
   - `致命的` / `要修正` / `検討` の三段階で仕分けて伝える
   - 全文を貼らない。**何を直すのかと、なぜ直すのかだけ**を伝える

5. **反映する**
   - `致命的`・`要修正` は本文に反映する
   - `検討` は `HANDOFF.md` の「改善課題」へ追記し、次回以降に回す(その場で全部やらない)
   - **対応済みになった項目も消さない。**「(対応済み)何をどう直したか」を残し、**同じ間違いの再発を検出するための記録**として使う(第8〜10話の締めの反復が第26〜31話で再発した、という前例がある)

6. **反映した話数だけ、機械チェックを再実行する**

## コピー改稿から抽象化したレビュー観点(確定・2026-08-06新設)

掲載用あらすじを12版まで改稿する過程で受けた指摘を、本文レビューに一般化したもの。**いずれも「書き手には見えず、初見の読者には見える」タイプの欠陥**であり、`reader-reviewer`を呼ぶたびにこの観点を渡す。

1. **裏付けのない要約・言い換えを許さない。** 回想・まとめ・他者への説明で過去の出来事を言い換えるとき、元の描写と食い違っていないか。原稿は「後ろ向き」なのに要約で「尻込み」になる類の**格上げ・格下げ・性質のすり替え**を探す
2. **語彙は初出で定義されているか。** その話までの本文で意味が与えられていない作品内語彙を、当然のように使っていないか。**新規読者はその話から読み始める前提**で見る
3. **スケール表現・比喩は絵になるか。** 「雲より大きな翼」のような、大きさ・派手さを言っているだけで**読者が具体的な絵を結べない**表現になっていないか。大きさではなく**動きと機構**で見せているか
4. **接続詞は論理と一致しているか。** 「だが」「そして」「それでも」が、前後の実際の関係(対立/並列/譲歩)と合っているか。**合っていない接続詞は文の嘘**であり、読者は理由の分からない引っかかりとして感じる
5. **感情の因果は正しいか。** 気持ちの変化の理由として直前に置かれた出来事が、本当にその感情の原因か。時系列・重み付けの取り違え(「パーティを組んだから夢中になった」型)を探す
6. **隣接による誤読を探す。** 直前の文脈が次の文の解釈を歪めないか(変形能力の説明の直後に風・石畳を並べると変形対象に見える)。**多義語**(「掲示板」はネット掲示板に読める)が意図と違う絵を呼ばないか。**新規読者の目で、一文ずつ「この文はどう誤読できるか」を問う**
7. **職業スキルとクレストの絵が混ざっていないか。** 大人数の一斉技・詠唱付きの技は職業スキルの絵。クレストは「紋章が灯る→力が働く」の対応で書き分けられているか。**どちらの力か読者に判別できない戦闘描写は設定の混同を生む**
8. **能力の否定は動作で言えているか。** 「〜できない」「〜はない」が、**結果の否定(勝てない)に読めてしまわないか**。無いのは動作(飛べない・生み出せない)であって結果ではない、という書き分けができているか
9. **同語の近接反復。** 数行以内の「知っていた/知っている」型の反復は、意図した韻でない限り直す
10. **構造に酔った言い回しがないか。** 書き手が構造・対比をかっこいいと思って作った表現(「たった一つの動詞」型)は、**読者には言葉遊びにしか見えないことがある**。判定はCLAUDE.mdのキザ判定と同じ——**声に出して読んで恥ずかしいか**。恥ずかしければ、仕掛けを捨てて事実だけ残す
11. **本文の絵を切り出しても通じるか(引用耐性)。** 予告・あらすじ・Xの一行切り出しに使えそうな見せ場の文が、**文脈なしで読んで意味が通るか**。通らない場合、その見せ場は本文内でも文脈への依存が強すぎる可能性がある

## 機械チェック

```bash
# 文字数(4,000字前後が目安。短い分には可)と4文以上の段落
for f in manuscript/part01/epNNN.md ...; do python3 -c "
import re, sys
t = open(sys.argv[1]).read()
b = re.sub(r'<!--.*?-->', '', t, flags=re.S); b = re.sub(r'\`\`\`.*?\`\`\`', '', b, flags=re.S)
hits = [i for i, l in enumerate(t.split('\n'), 1) if l.startswith('　') and l.count('。') >= 4]
print(sys.argv[1], '| 文字数', len(b), '| 4文以上の段落', hits or 'なし')
" "$f"; done

# 「〜した。」の連続(戦闘・山場で4以上なら要修正)
python3 -c "
import re, sys
t = re.sub(r'<!--.*?-->', '', open(sys.argv[1]).read(), flags=re.S)
t = re.sub(r'\`\`\`.*?\`\`\`', '', t, flags=re.S)
run = []
for l in [l for l in t.split('\n') if l.startswith('　')]:
    if l.rstrip().endswith('た。'): run.append(l)
    else:
        if len(run) >= 4: print(len(run), '連続:', run[0][:40])
        run = []
" FILE

# 数値・金額の混入(Lv表記と見出しの話数を除く)
python3 -c "
import re, sys
t = re.sub(r'<!--.*?-->', '', open(sys.argv[1]).read(), flags=re.S)
t = re.sub(r'\`\`\`.*?\`\`\`', '', t, flags=re.S)
t = re.sub(r'Lv\d+', '', t); t = re.sub(r'^#.*$', '', t, flags=re.M)
for i, l in enumerate(t.split('\n'), 1):
    if re.search(r'[0-9]|[0-9]|ユン|\bY\b', l): print(i, l.strip()[:80])
" FILE
```

## 注意

- **この工程は省略できない。** `new-episode`の手順から必須で呼ばれる。3話たまったらレビューを通し、**未実行のまま4話目の下書きに入らない**
- **4文以上の段落チェックは誤検出する。** 「泣き声。日食。灰。渇き。飢え。そして——静けさ。」(第17話)のような**意図的な短文リズム**も引っかかる。機械的に割らず、密な説明文かどうかを目で判断する
- **エージェントが自己申告する文字数を鵜呑みにしない。** 過去に1,350字の乖離が起きている。必ず上のスクリプトで実測する
- **「特に問題ありません」だけの報告を受け取らない。** 指摘ゼロで返ってきた場合は、観点ごとの判断根拠が書かれているかを確認する(書かれていなければ差し戻す)
- **足す提案より削る提案を優先する。** 本作の一貫した課題は冗長さであり、レビューを加筆の口実にしない
- 反映によって話の骨格を変える必要が出た場合は、**独断で変えずユーザーに確認する**
